| 完了条件・確認事項 | 結果 |
|---|---|
| `MobHuntTarget.PlaceName` が手配書の「生息場所」の地域名と一致する | ✅ デイリーの対象 721 体すべてで、PlaceName は地域名（エリア名と同じものは 0 体）で、どれもそのエリアの地図に地域名ラベルがある。手配書の例（ウルハドシ → 南ザナラーン サゴリー砂漠）とも一致 |

## 詳細

### 1. 手配書の種類（`MobHuntOrderType`）

- `Type` 1 = デイリー、2 = エリート。
- `OrderStart` 〜 `OrderStart + OrderAmount - 1` が `MobHuntOrder` の主行 ID の範囲。主行 1 つが手配書 1 枚で、サブ行（`12.0`〜`12.4`）が 1 ページずつの対象。
- **ページ数: デイリーはすべて 5 ページ、エリートは 1 ページ。** 拡張や級による違いは無い。
- 拡張との対応は、対象のエリアの `TerritoryType.ExVersion` で確かめた（1 つの手配書が複数の拡張にまたがることは無い）。

- `MobHuntOrder.Rank` は 1〜5（エリートは常に 5）。用途は未確認だが、アプリでは使わない。

### 2. `MobHuntTarget` の `PlaceName`

- 手配書で使われている対象は 798 体（デイリー 721、エリート 77）。`MobHuntTarget` の 8 行（フェロック 4 兄弟など）はどの手配書にも出てこないので、取り込まなくてよい。
- デイリー: PlaceName はすべて地域名。エリア名と同じもの、地図にラベルが無いものは 0 体。
- **エリート: PlaceName はすべて 0（地域名なし）。** `Map` だけが入っている。→ 表示は「エリア名」だけにし、湧き地点の候補は別データ（HuntHelper）で補う（計画 §5.3 のとおり）。
- FATE の対象は 96 体（すべて新生エオルゼアのデイリー）。

### 3. 座標変換

計画 §5.2 の式は、どちらも正しかった。

- `Level`（ワールド座標）: `c = SizeFactor / 100`、`mapX = 41 / c * ((X + OffsetX) * c + 1024) / 2048 + 1`（`Z` と `OffsetY` で Y も同じ）
  - 種類 8（NPC）の Level 22,343 件を、Teamcraft の NPC の座標と比べて差 0.01 以下（100%）。差が 0.3 以上の 5 件は、同じ NPC が複数の場所にいて Teamcraft が別の場所を採ったもの。
- `MapMarker`（テクスチャ上のピクセル）: `mapX = 41 / c * X / 2048 + 1`
  - エーテライトのマーカー（`DataType` 3）107 件を Teamcraft のエーテライトの座標と比べて、差の中央値 0.17、最大 0.35。平均の偏りは X 0.006 / Y −0.004 で、`SizeFactor`（95〜400）による違いも無い。→ 式の誤りではなく、地図のアイコンを実際の位置から少しずらして置いているための差。ルート計算には十分な精度。
- **エーテライトの正確な位置も Level からは取れない**（`Aetheryte.Level[0]` は 107 件すべて Level シートに無い）。エーテライトの位置は `MapMarker`（`DataType` 3）を使う。

### 4. 手配書の FATE の位置

- `Fate.Location` は Level シートに無い（0 / 96 件）。ffxiv-datamining の過去のバージョンでも Level.csv の行数は同じくらい（約 6 万行）なので、エクスポートの取りこぼしではなく、元から Level シートに無い ID と考えられる。
- Teamcraft の `fates.json` には 95 / 96 件の位置があり、エリアはすべて `MobHuntTarget.Map` と一致した。無いのは「血濡れの猛犬「チュパカブラ」」（FATE 238、中央ラノシア）だけ。
- FATE の位置にいちばん近い地域名ラベルは、72 / 95 件で `MobHuntTarget.PlaceName` と違った（小さな地名ラベルが近くにあるため）。**手配書に出る地域名は PlaceName なので、表示には PlaceName を使い、FATE の座標はルート計算だけに使う**のがよい。

### 6. エリアの出口（エリア間のつながり）

- EXDSchema によると `MapMarker.DataKey` は `DataType` 1・2 のとき Map、3 のとき Aetheryte、4 のとき PlaceName（エーテネット）を指す。
  - **`DataType` 1 がエリアの出口**（全体で 765 件）。
  - `DataType` 2 は ID ダンジョンなどの入口（例: カルン埋没寺院、次元の狭間）。つながりには使わない。
- 対象のいるエリア 47 か所から出口を 143 件取り出せた。フィールド同士のつながりはおおむね往復でそろっている。片方向になっているのは、ほとんどが行き先が街（今回は街の地図を対象外にしたため）。
- 補正リスト（`scripts/zone-links.overrides.json`）が必要なもの:
  - **船・定期便も出口として入っている**: 西ザナラーン → リムサ・ロミンサ（ベスパーベイの定期船）、西ラノシア → 西ラノシア（幻影諸島への船）など。→ 補正リストで除く。
  - ハウジングエリア（ラベンダーベッド、ミスト・ヴィレッジ、ゴブレットビュート）、コンテンツの入口（ウルヴズジェイル係船場、モルディオン監獄、オムファロス、パンデモニウム正門、神門の間 など）も出口として入っている。→ 行き先がフィールドか街でないものは除く。
  - 街を通らないと行けないエリアが多い（例: 紅玉海 ↔ クガネ、ヤクテル樹海 → トライヨラ、サベネア島 → ラザハン、リビング・メモリーは出口なし）。→ M1 では街の地図もグラフに入れる。
- `TerritoryType.AetherCurrentCompFlgSet` によると、対象のいるエリアはすべて飛行できるエリア。ただし「どの出口が飛行しないと通れないか」はデータから分からないので、計画どおり補正リストで指定する。

### 7. データからは確かめられなかったこと

- **デイリー／ウィークリーのリセット時刻**: ゲームデータには無い。計画の想定（日次 15:00 UTC = 0:00 JST、週次 火曜 8:00 UTC = 17:00 JST）のまま M2 で実装し、ゲーム内で確認する。
- **船・飛行が必要な区間の網羅性**: 上の補正の洗い出しは M1 で、生成したグラフを見ながらゲーム内で確認する。
