# M3 OCR レポート

[開発計画書](../PLAN.md) の M3（手配書の読み取り）の実装内容。ゲーム内での確認は [`CHECKLIST.md`](./CHECKLIST.md)。

## 実装したもの

| 機能 | ファイル |
|---|---|
| スキャン画面（カメラ／画像選択 → 範囲の調整 → 読み取り → 候補から選んで追加） | `app/scan-tab.tsx` |

| 正解率の測定 | `scripts/m3/eval-ocr.mjs` |

## 仕様のポイント

- **入力**: 「カメラ」「スクリーンショット」のタブで切り替える。既定はスマホ（タッチ操作、`pointer: coarse`）ならカメラ、PC ならスクリーンショット。カメラが使えないときはスクリーンショットに切り替える。スクリーンショットは、Ctrl+V（⌘V）での貼り付け、「クリップボードから貼り付け」ボタン、ファイル選択のどれでも取り込める。カメラ（`getUserMedia`、背面カメラ）か、スクリーンショット。カメラのプレビューは、文字の書いてある部分（モブ手配書 n/5・討伐対象・討伐体数・生息場所の 4 行）だけを映す横長の帯（幅:高さ = 3:1。上下に余白をつけ、中央の 4.5:1 がガイド枠の目安）で、行の区切り線とラベルを重ねて表示する。撮影（または画像の選択）をしたらすぐに読み取って候補を出す（範囲を選ぶ操作は無い）。切り出しは、カメラはプレビュー全体（ガイド枠の上下の余白も読み取り、枠からずれても読めるようにする）、スクリーンショットは画面の下部（`SCREENSHOT_CROP`）。
- **前処理**: 切り出し → 小さければ最大 3 倍まで拡大 → グレースケール → （写真のときだけ）ぼかし → コントラスト補正 → 大津の二値化（多いほうの色を背景とみなし、黒文字・白背景にそろえる）。ぼかしはカメラ撮影のときだけ入れる。
- **認識**: Tesseract.js 7（`jpn`、LSTM のみ、`tessdata_best_int` 2 MB）。ワーカー・WASM・学習データは `public/ocr/` に同梱したものを使い、外部の CDN へは取りに行かない（AGENTS.md）。最初に読み取るときだけ読み込み、ワーカーは使い回す。
- **項目の抽出**: ラベル（「討伐対象」「討伐体数」「生息場所」）の誤認識を 1 文字まで許して値を取り出す。`n/5` からページを読み、手配書 1 枚ぶんのページがそろっていなければ「まだ読み取っていないページ」を出す。
- **辞書照合**: モブ名（NFKC・かな・紛らわしい文字 `ー/一`、`ロ/口`、`カ/力` など・I/l/1 をそろえた文字列）とのレーベンシュタイン距離で点数をつけ、上位 3 件を候補にする。「生息場所」が地域名・エリア名と合うと加点（同名のモブの区別にも効く）。ラベルが読めなかったときは全文の中から名前を探す（短い名前の偶然の一致を避けるため、名前が長いほど点が高い）。
- **確認・修正**: 認識結果と候補をラジオボタンで出し、選んだ候補を討伐体数つきで追加する（`source: "ocr"`）。確からしさが低いときは警告して、手配書タブの手入力へ誘導する。
- **サイズ**: OCR 用ファイルは `public/ocr/` に約 14 MB（コピーしたもの）だが、読み込むのは端末が使う 1 種類の WASM（約 3.9 MB）＋学習データ（約 2 MB）。スキャン画面で読み取りを押すまで読み込まない。

## 机上の検証（合成画像）

実際の手配書のスクリーンショット・写真は手元に無いので、手配書の下部パネルに似せた画像を、サンドボックスにある日本語フォント（WenQuanYi Zen Hei）で合成して、実際の画面を動かして測った（`scripts/m3/eval-ocr.mjs`）。**あくまで動作確認で、完了条件の正解率ではない**（実機のフォント・色・UI サイズ・撮影条件とは違う）。

| 条件（各 30 枚、デイリーの対象からランダム） | 上位 1 件 | 上位 3 件 |
|---|---|---|
| スクリーンショット風（1280×720、下部パネルのみ合成） | 100% | 100% |
| スマホ撮影風（ぼかし・コントラスト低下・1.5° 傾き。範囲を手で指定していた旧 UI での測定） | 96.7% | 100% |

撮影風の画像では、ラベル「討伐対象」などが読めず、全文からの名前探しに切り替わるケースがあった（その場合も候補には正解が入る）。本番の確認は [`CHECKLIST.md`](./CHECKLIST.md) の最小版（スマホで 1 枚試す）にとどめる。

## 既知の制限・次に回すこと

- 方針変更: 正解率の厳密な測定（30 枚以上）はやめ、スマホで 1 枚試す最小限の確認にした。精度の不具合は、見つかったときに直す。
- スクリーンショットは画面下部を固定の範囲で切り出す。UI の位置が大きく違うと外れる可能性がある（そのときは範囲を調整する）。実際のスクリーンショット 1 枚（ベテラン・モブ手配書：上級）で、1 件目に正解が出ることは確認した。
- Service Worker によるキャッシュとオフライン対応は M4（PWA）で行う。
- 測り方: `npm run build` のあと `node scripts/m3/eval-ocr.mjs <画像フォルダ> --labels <正解.json> [--photo] [--crop x,y,w,h]`（Playwright が必要）。
